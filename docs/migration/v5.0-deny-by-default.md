# Migrating to deny-by-default (`NodusRuntime`)

**Who this affects:** anyone embedding Nodus in Python via `NodusRuntime`.

**Who it does not:** anyone using `nodus run`, `nodus workflow-run`, the REPL, or
any other CLI command. Those are unchanged, deliberately — see §4.

---

## 1. What changed

`NodusRuntime` now **refuses** the three host capabilities unless you grant them:

| Constructor argument | Was | Is |
|---|---|---|
| `allow_subprocess` | `True` | **`False`** |
| `allow_network` | `True` | **`False`** |
| `allow_env` | `True` | **`False`** |

`allowed_paths` is unchanged — it already defaulted to a CWD jail.

Separately, **a Nodus program can no longer write into `.nodus/`** — the workflow
store, graph state and bytecode cache. This applies everywhere, CLI included.

## 2. The fix, in one line

Grant what the script you are hosting actually needs:

```python
# before
runtime = NodusRuntime()

# after
runtime = NodusRuntime(allow_subprocess=True, allow_network=True)
```

The error tells you which flag, so you can also just run it and read:

```
Blocked: subprocess execution is not granted;
         pass allow_subprocess=True to NodusRuntime to allow it
```

Grant the narrowest set that works. If a script only fetches URLs, it does not
need `allow_subprocess`.

## 3. Why

All three external architecture audits of Nodus independently identified the
host-function boundary as the highest-leverage change available — convergence
that occurred on no other finding. Audit 03 put the gap plainly:

> *"Nodus is three days of work from a claim no competitor can make… The
> chokepoint is built; the door is propped open by registering subprocess and
> http by default."*

The lock has been built over #405's earlier stages: a policy consulted at both
chokepoints, per-call and per-argument decisions, `capability_denied` events, and
an unbypassable floor. **Leaving the defaults permissive would have meant
shipping a lock on an open door.** In-process capability confinement of code you
did not write is one of only two things Nodus offers that a Python library
structurally cannot; a default that gives it away is not a default worth keeping.

## 4. Why the CLI is exempt

`nodus run script.nd` is unchanged, and this is a decision rather than an
oversight.

The domain this protects is **work you did not fully author** — code arriving
from a model, a colleague, or a queue, hosted inside your process. A developer
running a script they just wrote is not that. A CLI that refused to shell out
would be like `python` refusing to open sockets: friction with no threat model
behind it.

The two paths are genuinely separate in the code — `nodus run` builds a `VM`
directly and never constructs a `NodusRuntime` — so this is a real boundary, not
a special case. A test pins both halves.

If you want a jailed CLI run, the flags already exist:
`nodus run script.nd --allow-paths <dir>`.

## 5. Writing to `.nodus/`

If a program of yours wrote into `.nodus/`, it will now fail. This is the
capability **floor**, which no policy can override.

`.nodus/` holds the workflow store, graph state and the bytecode cache. Before
this, a guest script could overwrite a run record — verified: it wrote
`{"forged": true}` over `.nodus/workflow_framework/runs/<id>.json` and the run
reported success. That is forging durable state, and it is the reason the floor
ships with a rule rather than empty.

Reads are untouched. Matching is on normalised path *segments*, so
`my.nodus-notes.txt` is unaffected and `../.nodus/x` is not.

**Use a different directory** for your own data. If you need the store itself,
reach it from the host side in Python, not from guest code.

## 6. Checklist

- [ ] Find every `NodusRuntime(` in your codebase.
- [ ] Run your tests; the errors name the flag to add.
- [ ] Grant the narrowest set that works, per runtime rather than globally.
- [ ] Check for guest code writing under `.nodus/`.
- [ ] Consider whether you now want a `capability_policy` as well — the flags are
      all-or-nothing per category, while a policy decides per call and can read
      the arguments. See
      [`docs/design/v5/02-capability-policy.md`](../design/v5/02-capability-policy.md).

## 7. If you disagree with the default

`NodusRuntime(allow_subprocess=True, allow_network=True, allow_env=True)`
restores the previous behaviour exactly, in one place. There is no global switch,
deliberately: a process-wide "make it like it was" flag is the thing that gets
set once in a shared config and then forgotten.
