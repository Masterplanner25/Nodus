# Nodus Projects

Nodus projects are rooted by a `nodus.toml` manifest.

## Manifest

Minimal example:

```toml
[package]
name = "example"
version = "0.1.0"

[dependencies]
json = "1.0.0"
```

The `[package]` table defines project metadata. Its keys are `name`, `version`,
`registry_url`, and `entry`.

The `[dependencies]` table defines local path or version-based dependencies.

Those two tables are the whole manifest. **Anything else is refused, not
ignored** — a `[project]` table, or a misspelled `verison`, fails the load with a
message naming what it found and what was expected:

```
nodus.toml declares things Nodus does not read:
  unknown table [project] -- did you mean [package]?
  unknown table [runtime] -- Nodus has no [runtime] table

nodus.toml supports [package], [dependencies], and [package] keys: name,
version, registry_url, entry.
```

A manifest is the worst place to accept a declaration silently, because it looks
like it worked. Before 5.3.0 every unknown table was read and discarded (#490).

### `entry`

`entry` names the file `nodus run` starts from, relative to the project root:

```toml
[package]
name = "example"
version = "0.1.0"
entry = "workflows/bootstrap.nd"
```

Omit it and the `src/main.nd` convention applies. It must resolve inside the
project root — a manifest is data, and an `entry` pointing outside its own tree
is refused.

## Project Layout

Recommended layout:

```text
my-project/
  nodus.toml
  src/
    main.nd
  .nodus/
    cache/
    deps.json
    modules/
```

`src/main.nd` is the default project entrypoint, used when `[package]` declares
no `entry`.

## Commands

Initialize a project:

```bash
nodus init
```

This creates:

- `nodus.toml`
- `src/main.nd`
- `.nodus/cache/`
- `.nodus/modules/`

Runtime execution may also create `.nodus/deps.json`, which records the resolved module dependency graph used for incremental compilation.

Install declared dependencies:

```bash
nodus install
```

Add a dependency from the local registry:

```bash
nodus add json
```

Remove a dependency:

```bash
nodus remove json
```

Run a script directly:

```bash
nodus run main.nd
```

Run a project directory:

```bash
nodus run .
```

If `nodus run` is executed inside a project root with no script argument, it runs `src/main.nd`.

If `nodus run <file>` is given an explicit file path, Nodus runs only that file even when `nodus.toml` is present.

## Lockfile

Installed dependency state is recorded in `nodus.lock`.

This file is generated by tooling and should be kept under version control for reproducible installs.

## Resolution Order

When importing modules, Nodus checks in this order:

1. project modules
2. `.nodus/modules`
3. stdlib
